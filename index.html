02 / ARCHITECTURE구조 설명

PostgreSQL 안에서 동작하는 Citus

Elastic Clusters는 여러 Flexible Server Node를 Citus로 연결하는 Managed Distributed PostgreSQL입니다. Citus는 PostgreSQL 앞의 별도 Database Engine이 아니라 각 PostgreSQL Instance 내부의 Extension입니다.

Distribution Key Predicate와 Table Colocation은 Network Round Trip과 Cross-shard 연산을 줄이는 데 유리합니다. 반대로 Fan-out과 Data Movement는 비용을 늘릴 수 있습니다.

테이블 생성만으로 자동 분산되는 것은 아닙니다. MVU도 잘못된 Shard Key, Hot Shard 또는 SQL Compatibility 문제를 해결하지 않습니다.

장표에 기재된 제약: Node-count Scale-in, Single User Database, Extension / SQL / 관리 기능 제약. 실제 적용 시 최신 제품 문서를 확인해야 합니다.

05 / ELIGIBILITY검증 당시 상태

이번 시험에서 확인한 Upgrade Path

Engine Version 지원 ≠ Source → Target MVU Path 지원
PG18 Cluster 생성이 가능하더라도 모든 PG17 / Citus 조합의 Upgrade가 가능하다는 뜻은 아닙니다.

확인된 경로: PG 17.11 + Citus 13.3 → PG 18.6 + Citus 14.1. 이 페이지의 주요 부하 측정은 Japan East 2-node 환경에서 수행했습니다.

실제 적용 전에는 공식 문서에서 사용 Region, Source / Target Version, Extension 호환성과 현재 제공되는 실행 방법을 확인해야 합니다. 이 시험 결과는 제품 지원 목록을 대신하지 않습니다.

09 / BLOCKER TESTS별도 1-node 시험

사전 점검 대상과 시험 범위

별도 1-node 시험에서 Logical Replication Slot, Prepared Transaction, 의존 View, Event Trigger와 Extension 등의 점검 대상을 함께 구성했습니다. 운영에서는 공식 문서의 Upgrade 사전 점검 목록과 고객 구성을 대조해야 합니다.

Trial조건관측 결과
1사전 점검 대상 객체 존재2분 36초 후 Ready · PG17 유지. 측정 중 연결 중단 없음
2동일 객체 구성 + 작업 상태 추적작업 실패 확인. 접속 40회 성공
3객체 제거와 요청 구성 변경 후 재시험약 13분 내 PG18.6 확인, 연결 불가 약 6분 25초
복수 조건을 함께 변경한 시험이므로 개별 객체의 영향이나 성공 원인을 확정하지 않습니다. 작업 완료 여부와 실제 Engine Version을 함께 확인해야 합니다.
