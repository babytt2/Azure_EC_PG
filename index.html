2) 시각화: 왜 Reconnect ≠ Ready 인가

3) 운영 체크리스트(요약)

  • 사전: blocker pre-check, rehearsal, probe 준비, authConfig 포함
  • 진행: write 중지, async 상태 추적, 요청~Ready 전체 구간 관리
  • 사후: version/metadata/consistency/auth/SLO 확인 후 단계적 write 재개

4) 고객 Q&A / 확인이 필요한 이슈

Q1. 업그레이드 후 Entra 인증이 꺼질 수 있나요?

실측에서 version-only 요청 시 Entra auth 초기화 이슈를 관찰했습니다. 요청에 authConfig를 명시하고, 업그레이드 후 신규 로그인 검증이 필요합니다.

Q2. DB 연결이 되면 바로 서비스 재개해도 되나요?

아니요. Ready, shard/metadata, distributed write consistency, auth, app SLO까지 확인한 뒤 재개해야 합니다.

Q3. 현재 단계에서 가장 중요한 운영 포인트는?

Public Preview 단계에서는 pre-check → rehearsal → controlled upgrade → post-validation을 표준 절차로 운영하는 것이 핵심입니다.

Q4. 추가 확인이 필요한 Open Item은?
  • Entra auth reset 동작 의도 여부
  • 재기동 직후 write visibility anomaly 원인
  • Elastic 전용 pre-check/validation API 로드맵
  • Korea Central 지원 상태 및 일정
